# Data dictionary for the expert reference set

The expert review was conducted in Korean. The guideline handed to the reviewers (`data/expert_pkg/audit.txt`), the two reviewers' verdict files (`rA.csv`, `rB.csv`), the adjudication files (`adjudication_17*.csv`), the review sheet template (`data/gt/gt_review_unit.csv`) and the reviewers' remarks carried into `data/results/fp_types.json` / `tca_pilot_rows.json` were translated into English with the fixed vocabulary below; the verdicts, rules, evidence locations, ids and every number are unchanged. `scripts/derive_results.py`, `scripts/verify_numbers.py`, `scripts/orig/final/*.py` and `scripts/orig/final_scripts/tca_pilot.py` read the English column names and labels.

## Columns of `rA.csv` / `rB.csv` (455 rows, one per sampled function)

| column | meaning |
|---|---|
| `id` | blinded item id `G001`–`G455` (order randomised; `unit_map_internal.json` maps it to the function and unit) |
| `function` | function name |
| `unit` | the compilation unit (`.c` file) the verdict is about |
| `hint` | hint given to the reviewer when the function is defined in an included file or header (9 rows) |
| `verdict` | `1` entry point, `0` not an entry point, `?` cannot be decided inside the unit (registration lies in another file) |
| `rule` | the rule that justifies the verdict (see below) |
| `evidence` | evidence locations, `path:line` separated by `;` |
| `remark` | the reviewer's free-text remark |

## Columns of the adjudication files

`adjudication_17.csv` lists the 17 items where the two verdicts were `1` vs `0`. The reviewers were blinded as `reviewer_X` / `reviewer_Y`; `adjudication_17_key_internal.json` says which of them is reviewer A or B for each row. Columns `reviewer_X_verdict`, `reviewer_X_rule`, `reviewer_X_evidence`, `reviewer_X_remark` (and the same for `Y`) repeat the two original verdicts; `adjudicated_verdict`, `adjudicated_rule`, `adjudicated_evidence`, `adjudication_reason` are the adjudicator's verdict, rule, evidence and reason. `adjudication_17_reply.csv` is the adjudicator's first reply, `adjudication_17_final.csv` the result after discussion with the reviewers; its extra column `revised` is non-empty for the 5 items that changed in that discussion (4 verdict changes, 1 reason-only change).

`gt_review_unit.csv` is the empty review sheet generated by `scripts/orig/fpea_pass/sample_gt_unit.py` (`verdict(1/0/?)`, `rule`, `remark`).

## Verdict rules (`rule`)

Positive rules (verdict `1`), in the priority order used by the guideline `init-exit > probe-remove > irq > teardown > deferred > op-table`:

| label | meaning |
|---|---|
| `op-table` | stored in a function-pointer struct (operations table) that the framework or another unit calls |
| `irq` | registered as an interrupt handler (`request_irq` family) |
| `probe-remove` | driver `probe` / `remove` / `shutdown` / `suspend` / `resume` |
| `teardown` | registered as a resource-release callback (`devm_add_action` family and the like) |
| `deferred` | registered as a deferred-execution callback (workqueue, timer, tasklet, URB/DMA completion, ...) |

Negative rules (verdict `0`):

| label | meaning |
|---|---|
| `internal-helper` | only called directly by name, inside (or outside) the unit |
| `exported-service` | `EXPORT_SYMBOL`ed and called directly by name from other modules |
| `sync-callback` | passed to an external function but only invoked before that call returns, never retained |
| `internal-dispatch` | stored in a struct or variable local to the unit and only called indirectly inside the unit |
| `comparison` | the address is only compared (`==`, `!=`) or used as an identity key, never called |

Undecidable (verdict `?`):

| label | meaning |
|---|---|
| `other-file` | the registration that would make it an entry point is in another `.c` file (15 items, all `?` by both reviewers) |

In derived files the suffix `(adjudicated)` marks a rule taken from the adjudicator rather than from an agreeing pair of reviewers, and `A/B` (for example `internal-dispatch/sync-callback`) marks a pair that agreed on the verdict but gave different rules.

## Where the labels are used

- `data/results/fp_types.json`: `fp_by_rule`, `A_rules`, `B_rules`, `tp_rules` and the `rule` / `note` of every FP item use the labels above (`note` is the reviewer's remark).
- `data/results/tca_pilot_rows.json` / `tca_pilot.log`: `rule` per pilot row.
- `scripts/verify_numbers.py` checks the rule distributions of Table 3 and Table 5 against these labels.

`data/results/decomp.json` (link-layer decomposition by `scripts/orig/nosan/decomp.py`) uses the category keys `with C1`, `C2 (no C1)`, `C3/C5r (no C1/C2)`, `C4 only`.
